About Me

It’s been a good forcing function for actually synthesizing what I’ve been reading rather than just accumulating notes.

Open Source — GSoC 2026 with JdeRobot

I’m a selected contributor for Google Summer of Code 2026 with JdeRobot, working on Project #7: Optimizing the RoboticsBackend Docker Infrastructure and Migrating to Rootless Podman.

The short version of what I’m doing: the platform that powers JdeRobot’s RoboticsAcademy runs inside a monolithic Docker image that has accumulated years of build debt — nearly 60 image-altering layers, inconsistent cache purging, and heavy meta-packages like Aerostack2 and OMPL baked directly into the final image. My job is to fix that. The plan is to:

  • Restructure the build into a proper multi-stage pipeline, separating the compile environment from the runtime image
  • Prune the heavy ROS 2 source dependencies that aren’t needed at runtime
  • Migrate the whole thing to rootless Podman with correct UID mapping (--userns=keep-id) and GPU access via the Container Device Interface (CDI)

The RoboticsAcademy platform is used by students worldwide to learn robotics programming through browser-based simulations. Making it faster to download and start up has a direct impact on accessibility, especially for people on slower connections.

You can follow my progress on this blog, and the full project is tracked at github.com/TheRoboticsClub/gsoc2026-Kartik_Jangid.

Life Beyond the Terminal

I’m a competitive badminton player. I train daily and have been playing seriously for years — it’s not a casual hobby, it’s a structured practice with footwork drills, stroke mechanics, and match analysis.

Naturally, I started thinking about how to apply what I know from software to what I do on court. I’m currently building an offline ML pipeline that uses pose extraction to classify badminton strokes from recorded match videos. The idea is straightforward: extract body keypoints frame-by-frame using a pose estimation model, then train a classifier on the resulting sequences to identify stroke types (smash, drop, clear, drive, etc.). Everything runs locally — no cloud dependency, no API calls mid-session.

It’s still a work in progress, but it’s the kind of project that makes sense to me: something I actually want to use, built on techniques I want to understand deeply.
